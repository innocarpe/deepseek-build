## 2. PR unit plan (four sections)

Per [`ULTRAGOAL_PR_PLANNING.md`](../ULTRAGOAL_PR_PLANNING.md). VC001c is primarily **ops**; code PRs only if Release/npm cannot complete cleanly from the existing tag.

### 2.1 PR units

#### PR unit 1 — `chore(release): wait + attach 5.1.0 prebuilt assets` *(ops; no code PR if CI succeeds)*
- **Intent:** Ensure GitHub Release **`v5.1.0`** exists with platform tarball(s) expected by ADR 0009 install path (primary **`darwin-arm64`**).
- **Touches:** GitHub Release assets only (or local tag worktree + `./scripts/package-release-binaries.sh --upload` fallback per release-cycle).
- **Depends on:** VC001b; existing origin tag `v5.1.0`.
- **Parallelizable with:** none for the same tag/assets.
- **SemVer:** none (same **`5.1.0`**).
- **Tests:** `gh release view v5.1.0 --json assets`; asset name `deepseek-build-5.1.0-darwin-arm64.tar.gz` (or documented matrix).

#### PR unit 2 — `chore(release): human npm publish @5.1.0` *(human gate — ADR 0007)*
- **Intent:** Publish **`@innocarpe/deepseek-build@5.1.0`** so `dist-tags.latest` matches product floor after assets exist.
- **Touches:** npm registry only (no source change).
- **Depends on:** unit 1 assets green (postinstall downloads from Release).
- **Parallelizable with:** none.
- **SemVer:** publish existing **`5.1.0`** tree (not a bump).
- **Tests:** `npm view @innocarpe/deepseek-build version` → `5.1.0`; optional clean-prefix `npm i -g` + dual CLI `--version`.

#### PR unit 3 — `docs(product): VC001c ship-complete evidence` *(optional follow-up after green)*
- **Intent:** Close the lag narrative when Release + npm both match; link final run id / asset list.
- **Touches:** `docs/product/evidence/` (and board status lines if still saying “shipping”).
- **Depends on:** units 1–2 verified.
- **Parallelizable with:** pure vision design docs **only after** 5.1.0 floor stable (VC002 prefer).
- **SemVer:** none.
- **Tests:** doc links resolve; floor probes re-run green.

#### PR unit 4 — `fix(release): 5.1.1 hot patch` *(only if 5.1.0 ship broken)*
- **Intent:** Broken asset, wrong version string on prebuilt, or missing platform claimed by docs — **patch only**, not Spec 45 / L3.
- **Touches:** release scripts / packaging / minimal version bump via `./scripts/bump-version.sh 5.1.1`.
- **Depends on:** demonstrated failure of unit 1 or 2 for **`5.1.0`**.
- **Parallelizable with:** none.
- **SemVer:** **`5.1.1`** only (never invent `5.2.0` for packaging lag).
- **Tests:** check-semver + version-check + pack + platform test + new tag/Release/npm for `5.1.1`.

**Default path at this capture:** units **1 → 2** (CI run `31182417680` already in flight). Units 3–4 are conditional.

### 2.2 Sequential vs parallel

#### Sequential (must order)

1. **Tag exists** (done: `origin` `v5.1.0`) → **prebuilt assets / Release** (unit 1; run `31182417680` or manual fallback).
2. **Assets green** → **npm publish** (unit 2; human/credential).
3. **Registry + Release green** → **ship-complete evidence** (unit 3).
4. **Only if ship broken** → **`5.1.1` patch** (unit 4), then re-do 1–2 for the patch version.

#### Parallel (safe concurrent)

- **None** for Release asset upload and npm publish of the same version (shared public surface).
- **Do not** parallelize VC002+ feature work that assumes “5.1.0 installable from npm” until units 1–2 pass.
- Docs-only vision rebase already on `main` does **not** block waiting on CI; do **not** open a second “ship 5.1.0 theme” feature PR.

| Policy | Rule for VC001c |
|--------|------------------|

| If unit 4 fires | Single `fix/…` or `chore/release-5.1.1` branch → PR → merge commit → tag `v5.1.1`. |
